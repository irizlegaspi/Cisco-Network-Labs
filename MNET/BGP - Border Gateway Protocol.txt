BGP - Border Gateway Protocol
a type of routing protocol

GENERAL TYPES OF ROUTING PROTOCOL
1. IGP (iBGP)- Interior Gateway Protocol
Routing within the same autonomous systems
Uses Metrics to determine best path
Ex. RIP, EIGRP, OSPF


2. EGP (eBGP) - Exterior Gateway Protocol
Routing within different autonomous systems
Uses metric called Path Attributes/PA
Ex. BGP


AS - Autonomus System - Group of network devices within the same organization or company.



TYPES OF BGP
1. iBGP - Implemetation of BGP within the same AS. 
BGP routing within the same AS

2. eBGP - implementation of BGP within different AS.
BGP routing within different AS

How do BGP routers establish neighbor relationships?
1. Router tries to establish a TCP connection using port 179 and using 3-way handshake.
(OSPF and EIGRP does not use TCP, UDP and port and does not use 3-way handshake, they only uses protocol)

2.  When the 3 way handshake completes, BGP send its first packet called BGP OPEN MESSAGE = Hello

3. If all parameters are ok and verified, the 2 routers would become neighbors, and will now be in the ESTABLISHED state.



BGP Neighbor States:
1. IDLE - BGP is administratively down, or is waiting for the next attempt (no neighbors yet).

2. CONNECT 
 --> BGP  is waiting for TCP request connection to be completed
 --> 3-way handshake state
	 SYNTAX:
	   conf t
	   router bgp <as#> (idle state)
	   neighbor  <ip addr> remote-as <as# of neighbor> (connect state)
--> Once configured your router will send BGP TCP request

- OSPF, EIGRP uses multicast addressing while BGP uses UNICAST - it can directly send message to its neighbor

Good question, Riz! In BGP, the neighbor IP address you specify with neighbor <ip addr> remote-as <as#> doesn't necessarily have to be directly connected. Unlike OSPF or EIGRP, which rely on direct Layer 2 adjacency, BGP neighbors can establish sessions even if they're several hops away.

However, if the neighbor is not directly connected, you'll need to ensure:

The IP address is reachable (via an IGP like OSPF/EIGRP or static routes).

You configure ebgp-multihop (neighbor <ip addr> ebgp-multihop <hops>), especially for eBGP neighbors, as eBGP by default expects direct connectivity.

Your source interface or update-source is correctly set (neighbor <ip addr> update-source <interface>), particularly if using a loopback.

For iBGP, the requirement for direct connection doesn't exist, but you must have full mesh connectivity or use route reflectors or confederations.

4. OPENSENT
- TCP connection is ok
- BGP Open ("hello") has been sent, but neighbor open message has not been received yet.

5. OPENCONFIRM
- Open message are both sent and received
- Just waiting for a BGP keepalive message to check if there are neighbor parameter mismatch

6. ESTABLISHED
- All neighbor parameters match, the neighbor relationship works & BGP peers can now exchange BGP updates.
